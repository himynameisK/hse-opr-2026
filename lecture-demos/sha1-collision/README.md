# Коллизия SHA-1: проверьте сами

Два PDF из проекта [SHAttered](https://shattered.io) (Google + CWI Amsterdam, 2017).
Первая практическая коллизия SHA-1: около 6500 процессорных лет вычислений.

Запустите `./проверить.sh` или пройдите шаги руками.

## 1. Один и тот же SHA-1

```bash
shasum -a 1 shattered-1.pdf shattered-2.pdf
```
Оба файла дают `38762cf7f55934b34d179ae6a4c80cadccbb7f0a`.

## 2. Но файлы разные

```bash
cmp shattered-1.pdf shattered-2.pdf     # differ: char 193
shasum -a 256 shattered-1.pdf shattered-2.pdf   # SHA-256 разный
```

## 3. Коллизия переживает дописывание в конец

```bash
for f in 1 2; do cat shattered-$f.pdf > app-$f.bin; printf 'ХВОСТ' >> app-$f.bin; done
shasum -a 1 app-1.bin app-2.bin
```
Хеши по-прежнему совпадают. Именно поэтому такие коллизии опасны: из пары
«безобидный документ / вредоносный документ» можно сделать пару настоящих файлов.

## 4. Но не переживает дописывание в начало

```bash
for f in 1 2; do { printf 'X'; cat shattered-$f.pdf; } > pre-$f.bin; done
shasum -a 1 pre-1.bin pre-2.bin
```
Хеши разошлись.

## 5. Что скажет Git

```bash
git hash-object shattered-1.pdf shattered-2.pdf
```
Разные хеши. **Почему?**

Git хеширует не файл, а строку `blob <размер>\0<содержимое>`. Заголовок `blob 422435\0` —
это 12 байт перед содержимым. Они меняют внутреннее состояние SHA-1 к моменту подобранных блоков,
а блоки подобраны под конкретное состояние. Дело не в выравнивании: префикс ровно
в 64 байта тоже ломает коллизию.

Заголовок объекта был придуман ради разделения типов, а заодно случайно защитил Git
от первой практической атаки на SHA-1.

Отдельно: с 2017 года Git использует реализацию SHA-1 со встроенным детектором известной
атаки. Ценой примерно двукратного замедления хеширования, незаметного на фоне ввода-вывода.
