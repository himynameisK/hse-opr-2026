# Занятие 1 · После `git add .`

**60 минут вместе с разбором.** Разработчик закончил две независимые правки и
выполнил `git add .`. Вместе с кодом в индекс попали локальные файлы. Подготовьте
два понятных коммита, которые не стыдно отправить на ревью.

## Подготовка

Из корня репозитория курса:

```bash
make lab1
cd ~/opr-lab01/shop
```

Репозиторий уже находится в состоянии сразу после `git add .`. Ничего дополнительно
менять в коде не нужно: обе задачи реализованы, тесты написаны.

## Что находится в индексе

- исправление применения скидки и тест к нему;
- исправление отображения отрицательной суммы и тест к нему;
- `.env.local` и `debug.log`, предназначенные только для вашей машины.

Изучите подготовленные изменения через `git status` и `git diff --staged`.

## Что нужно получить

1. Уберите подготовленные изменения из индекса, сохранив их в рабочем дереве.
2. Добавьте локальные файлы в `.gitignore`; они не должны попасть в историю.
3. Сделайте один коммит с исправлением скидки и соответствующим тестом.
4. Сделайте второй коммит с исправлением форматирования и соответствующим тестом.
5. Порядок двух коммитов может быть любым. После каждого коммита тесты должны проходить
   (`python3 -m unittest discover -p 'test_*.py'`).
6. Сообщения должны объяснять изменение; `WIP`, `fix` и `lab1` не подходят.
7. `.gitignore` можно включить в любой из двух коммитов или закоммитить отдельно.

Перед каждым коммитом проверьте его содержимое через `git diff --staged`.

## Проверка

```bash
./check.py
```

Ожидаемый результат:

```text
PASS: создано два самостоятельных коммита
PASS: каждый коммит содержит одну задачу и её тест
PASS: тесты проходят после каждого коммита
PASS: локальные файлы не попали в историю и игнорируются
PASS: рабочее дерево чистое
```

Покажите преподавателю результат и ответьте на вопрос: зачем здесь понадобился
индекс, если в начале все изменения уже были добавлены командой `git add .`?
