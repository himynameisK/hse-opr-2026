# Занятие 11 · Docker 2 сломанные контейнеры

Одиннадцать маленьких сервисов, и каждый работает не так
-порт проброшен, а ответа нет;
-образ весит сотни мегабайт;
-токен виден любому, кто скачал образ;
-после перезапуска пропали данные. Найти причину и починить — Dockerfile,
-entrypoint или compose.yaml, — не трогая код приложения.

Сначала — вводная задача 0 на поиск секретов; обязательные задачи с автоматической проверкой — **1–6**, задачи 7–11 — плюсом.

## До занятия: скачать образы

На паре сеть общая и медленная, а базовые образы весят сотни мегабайт.
Дома, с запущенным Docker:

```bash
docker pull himynameisk/hackme
docker pull python:3.12-slim
docker pull golang:1.23-alpine
docker pull alpine:3.20
docker pull redis:7-alpine
docker pull postgres:16-alpine
```

Задача 2 ставит пакет с PyPI — на занятии нужен интернет, но всего на пару
сотен килобайт.

## Где это делается

Там, где у вас работает `docker` Docker Desktop на macOS и Windows, Docker
Engine на Linux, WSL с Docker Desktop. Права root не нужны, но на Linux ваш
пользователь должен быть в группе `docker` (`docker ps` без sudo работает).
Нужны `docker compose` (v2, через пробел) и BuildKit — в Docker Desktop
и свежем Docker Engine они есть. Python 3.8+.

```bash
git pull && make lab11       # без make: bash lab11-docker/setup.sh
cd ../opr-lab11
```

Развернётся рядом с репозиторием курса, в `../opr-lab11` — точный путь
скрипт печатает последней строкой, `Готово: …`.

```text
задачи/1-port/ … 11-signals/    по каталогу на задачу: сервис и УСЛОВИЕ.txt
check.py                        проверка
README.md                       этот файл
```

## Задачи

Работаете прямо в каталоге задачи: `cd задачи/1-port`, читаете `УСЛОВИЕ.txt`,
собираете и запускаете сами, правите. В условии сказано, какие файлы менять
можно; код приложения — нельзя.

| № | Задача | Что чините |
|---|---|---|
| 0 | Найти два секрета в учебном образе | Исследование образа |
| 1 | Порт проброшен, а сервис не отвечает | Dockerfile |
| 2 | Каждая сборка ставит зависимости заново | Dockerfile, .dockerignore |
| 3 | Утилита не принимает аргументы | Dockerfile |
| 4 | Токен утёк вместе с образом | Dockerfile |
| 5 | Маленький сервис в огромном образе (Go) | Dockerfile |
| 6 | После перезапуска данные пропали | compose.yaml |
| 7 | Сервис падает при первом запуске | compose.yaml |
| 8 | Витрина не видит api, зато видит базу | compose.yaml |
| 9 | Сервис работает от root | Dockerfile |
| 10 | docker logs молчит | Dockerfile |
| 11 | docker stop ждёт, а потом убивает | Dockerfile, entrypoint.sh |

Чем пригодится: `docker logs`, `docker exec`, `docker inspect`,
`docker history --no-trunc`, `docker image ls`, `docker build --progress=plain`,
`docker compose ps -a`, `docker compose logs`.

## Проверка

```bash
python3 check.py         # все задачи, на холодную — минуты три
python3 check.py 3       # только задача 3; можно несколько: 3 5 6
```

На Windows — `python check.py` или `py check.py`.

```text
Задача 1: FAIL (12 с)
  с хоста по опубликованному порту 127.0.0.1:57405 ответа нет: …
  а изнутри контейнера по http://127.0.0.1:8000/ служба отвечает: …
```

Проверка сама собирает образ из копии каталога задачи, запускает его
своей командой, стучится в сервис и смотрит `docker history`, `inspect`,
слои образа и логи — то есть проверяет поведение, а не текст файлов. Ваши
файлы она не меняет. Всё, что создала, называется `opr11-tN-…` и удаляется
в конце, даже если прервать её Ctrl+C. Если проверку убили жёстко
(закрыли терминал) — `python3 check.py --clean` уберёт остатки.

Порты на хосте выбирает Docker, поэтому проверке не мешают ни ваши
контейнеры, ни занятый 8080. Свои контейнеры, запущенные по условию,
убирайте сами: `docker rm -f …`, `docker compose down -v`.

## Если испортилось

```bash
bash lab11-docker/reset.sh        # из каталога курса: check.py, README и УСЛОВИЕ.txt как было
bash lab11-docker/reset.sh 3      # и задачу 3 целиком — снова сломанной, как в начале
bash lab11-docker/reset.sh все    # и все задачи
```

Ваш вариант задачи перед этим сохраняется в `бэкап/N-имя-дата/`,
изменённый `check.py` — в `check.py.bak`.
