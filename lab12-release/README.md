# Практика 12. Что сломал релиз

Вы отвечаете за выпуск учебного магазина. Нужно обнаружить ухудшение, связать его с версией, восстановить работу и объяснить решение по наблюдениям. Все покупки синтетические, внешних платежей нет.

## Подготовка до занятия

Нужны Docker с Compose и Python 3. Запускайте команды из каталога `lab12-release`. Первое скачивание образов может занять несколько минут: сделайте его заранее. Выделите Docker около 4 ГБ свободной памяти под стенд. На Apple Silicon закреплённый образ Metabase работает через эмуляцию amd64; первый запуск медленнее.

```bash
docker compose up -d --build
python3 bootstrap.py
docker compose ps
```

Скрипт напечатает ссылку на готовый Metabase. Его можно запускать повторно. Для работы не нужно самостоятельно собирать дашборды.

| Инструмент | Адрес | Вход |
|---|---|---|
| Grafana | http://127.0.0.1:13000/d/shop | Просмотр без входа |
| Metabase | http://127.0.0.1:13001 | `teacher@example.org` / `Lab12-local-only!` |
| Состояние магазина | http://127.0.0.1:18080/health | Без входа |

В Metabase откройте «Магазин: оплаты и выручка». Включите автообновление или обновляйте дашборд после переключения версии. Grafana обновляется каждые 5 секунд. Адреса доступны только с вашего компьютера.

## Задание на час

### 1. Снять исходное состояние — 10 минут

```bash
python3 lab.py release v1
```

Подождите две минуты. Найдите интенсивность запросов, долю HTTP-ошибок, p95 обработки и активную версию в Grafana. В Metabase найдите долю оплат и выручку. Запишите исходные значения и время.

### 2. Выпустить изменение и разобраться — 20 минут

```bash
python3 lab.py release v2
```

Дайте версии поработать две минуты. Найдите, какие показатели изменились. Смотрите разбивку по версии: общий показатель может скрыть ухудшение.

```bash
python3 lab.py logs
```

Сопоставьте время выпуска, метрики и причину в логах. Сформулируйте: «После выпуска … изменилось …; в логах …; поэтому я …». Не нужно переписывать сервис или настраивать инфраструктуру.

### 3. Восстановить работу и проверить — 10 минут

```bash
python3 lab.py release v1
```

Подождите две минуты. Проверьте свежие запросы и графики. Старые ошибки не исчезнут из скользящего окна сразу; это не означает, что возврат версии не сработал.

```bash
python3 lab.py check
```

Три PASS подтверждают выполнение действий. Они не заменяют объяснение: на что вы опирались и как убедились в восстановлении.

### 4. HTTP 200, но покупок меньше — 15 минут

```bash
python3 lab.py release v3
```

Подождите две минуты и обновите Metabase. Сравните HTTP-ошибки и долю оплат **для v3**. Прочитайте логи. Объясните, почему технический дашборд сам по себе недостаточен. Верните рабочую версию:

```bash
python3 lab.py release v1
```

### 5. Короткий разбор — 5 минут

Покажите преподавателю график ухудшения и восстановления, один лог с причиной, результат `check`. Ответьте: какой сигнал поймал v2, какой — v3, и какую проверку вы добавили бы перед следующим выпуском? Достаточно одного экрана с графиками и устного объяснения; большой отчёт не нужен.

## Что именно моделирует стенд

Генератор создаёт примерно две попытки оформления в секунду. Цена заказа — 1500 учебных рублей. Выручка считается только по оплаченным попыткам. Доля оплат — оплаченные попытки / все попытки оформления; это не конверсия посетителей сайта.

В PostgreSQL при первом старте добавлены 15 минут фоновой истории: одна успешная попытка в секунду с `synthetic_history=true`. Живой поток идёт примерно вдвое быстрее, поэтому абсолютное число заказов до и после старта сравнивать нельзя без учёта нагрузки. Проверка `check` фоновую историю исключает. Метрики Prometheus появляются только после запуска сервиса. Незавершённая последняя минута на графике естественно ниже полной.

Команда `release` переключает готовое поведение внутри одного образа. Это модель проверки релиза: сборка и выкладка разных образов, CI pipeline и canary здесь не реализованы. Время обработки в метрике исключает запись в БД и передачу HTTP-ответа. p95 оценивается по корзинам гистограммы, поэтому не обязан совпадать с задержкой конкретного запроса.

## Остановка и неполадки

```bash
docker compose stop
```

Следующий запуск: `docker compose up -d`, затем `python3 bootstrap.py`. История сохраняется; после перезапуска магазина активна v1. Для повторения задания смотрите текущее время: `check` учитывает и предыдущие прогоны, поэтому преподаватель проверяет свежие графики.

Если сервис недоступен: `docker compose ps`, затем `docker compose logs --tail=80 shop metabase`. Если порт занят другим приложением, остановите именно свой конфликтующий стенд или согласованно измените порты в Compose и Python-скриптах. Не останавливайте чужие контейнеры.

Не используйте `docker compose down -v` для обычной остановки: команда удаляет учебную БД, настройки Metabase и историю Prometheus. Полный сброс нужен только если вы намеренно хотите начать с пустого стенда; после него снова выполните команды подготовки.
