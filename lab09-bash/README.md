# Занятие 9 · Скрипт, который не ломается

Один боевой скрипт выкладки, семь закладок. Минут сорок.

## Где это делается

Где угодно, где есть bash 4+: виртуальная машина, WSL, контейнер, Git Bash.
Права root не нужны.

```bash
bash lab09-bash/setup.sh
```

Развернётся рядом с репозиторием курса, в `../opr-lab09`. Внутри — `deploy.sh`,
учебное приложение в `app/` и проверка.

На macOS системный `/bin/bash` версии 3.2 и ведёт себя иначе. Берите виртуалку
или контейнер — так же, как на занятиях 4 и 5.

## Зачем это нужно

Скрипт отработал, код возврата ноль, в выводе ничего подозрительного — а
релиз не выложен, журнал не сжат и каталог снесён не тот. **Bash по умолчанию
не защищает вас ни от чего:** необъявленная переменная — пустая строка,
упавшая команда — идём дальше, пробел в имени файла — два аргумента.

Здесь ровно такой скрипт: он «обычно работает».

## Задание

```bash
cd ../opr-lab09
./deploy.sh app          # так он запускается штатно
./check.py               # так проверяется
```

Проверка гоняет скрипт по семи сценариям: без аргумента, с несуществующим
каталогом, без файла `VERSION`, без отчёта, с отчётом без единой ошибки,
с журналом, в имени которого есть пробел. Каждый сценарий — своя закладка.

Сдано, когда семь строк `PASS` и код возврата 0.

**Чинить надо причину, а не симптом.** Обернуть всё в `|| true`, чтобы
проверка замолчала, не получится: половина сценариев требует как раз
ненулевого кода возврата.

Подсказки — на слайдах сегодняшней лекции. Там же чеклист боевого скрипта,
по которому удобно идти сверху вниз.

## Чем смотреть

```text
bash -n deploy.sh                синтаксис, ничего не выполняя
bash -x deploy.sh app            печатать каждую команду
PS4='+ строка ${LINENO}: '       добавить номера строк в трассировку
shellcheck deploy.sh             если установлен: найдёт почти всё разом
echo $?                          код возврата последней команды
set -euo pipefail                строка, с которой всё начинается
man bash                         разделы EXPANSION и Parameter Expansion
```

`shellcheck` ставится так: `apt-get install shellcheck`, либо проверьте
скрипт в браузере на shellcheck.net. Он найдёт не всё: три закладки из семи
он не видит, потому что это не синтаксис, а логика.

## Если всё сломалось

```bash
rm -rf ../opr-lab09 && bash lab09-bash/setup.sh
```

Разворачивает заново: исходный скрипт со всеми закладками и чистые данные.

## Приём

Семь строк `PASS` и ответ на вопрос по каждой закладке: **что именно
происходило и почему этого не было видно**. Второе важнее первого — починить
можно и копированием из чеклиста, а объяснить нельзя.
