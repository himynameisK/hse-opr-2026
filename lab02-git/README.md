# Занятие 2 · Конфликт и восстановление работы

**80 минут.** Вы продолжаете чужую ветку интернет-магазина. Пока в ней добавляли
доставку, в `main` появилась скидка. Git не может сам объединить две реализации
`total`. После слияния нужно вернуть ещё одно исправление, которое исчезло из ветки.

## Подготовка

Из корня репозитория курса:

```bash
make lab2
cd ~/opr-lab02/shop
```

Вы окажетесь в ветке `feature/shipping`. Интернет после развёртывания не нужен.

## 1. Объединить скидку и доставку

В `feature/shipping` реализована стоимость доставки. В `main` независимо добавили
процентную скидку. Выполните слияние `main` в текущую ветку и разрешите конфликт.

Итоговая функция должна:

- принимать и `discount_percent`, и `delivery`;
- применять скидку только к стоимости товаров;
- добавлять доставку после скидки;
- сохранять поведение при значениях по умолчанию.

Завершите слияние коммитом. Не выбирайте целиком одну сторону конфликта: тогда
потеряется либо скидка, либо доставка.

Проверьте промежуточный результат:

```bash
./check.py
```

Строка `PASS: конфликт разрешён` означает, что обе возможности сохранены.

## 2. Вернуть потерянное исправление

В `main` исправляли отображение отрицательных сумм, но затем ветку случайно
передвинули назад. Коммита нет в обычном `git log`, однако Git ещё помнит прежнее
положение ссылки `main`.

Найдите коммит с сообщением `Исправить формат отрицательных сумм`, изучите его
изменения и примените исправление к текущей ветке. Не передвигайте текущую ветку
назад: результат первой части должен сохраниться.

Промежуточная проверка:

```bash
./check.py
```

## 3. Слияние без конфликта, которое всё ломает

Пока вы занимались доставкой, две другие ветки жили своей жизнью:

- `feature/naming` — переименование в `catalog.py`;
- `feature/receipt` — новый файл `receipt.py` со сборкой чека и тест к нему.

Влейте обе в свою ветку. Git не выдаст ни одного конфликта: ветки правили разные
файлы. После этого запустите тесты:

```bash
python3 -m unittest discover -p 'test_*.py'
```

Разберитесь, почему тесты падают, хотя слияние прошло чисто, и почините. Менять
`catalog.py` обратно нельзя: переименование сделали намеренно, и оно остаётся.

Финальная проверка:

```bash
./check.py
```

Ожидаемый результат:

```text
PASS: конфликт разрешён, скидка и доставка работают вместе
PASS: потерянное исправление восстановлено
PASS: семантический конфликт найден и исправлен, тесты зелёные
PASS: рабочее дерево чистое
```

## Сдача

2. Почему потерянный коммит удалось найти, хотя его не было в обычном `git log`?
3. Почему в третьей части Git промолчал, хотя код после слияния был сломан?
   Что из этого следует для правила «зелёный pull request можно вливать»?
